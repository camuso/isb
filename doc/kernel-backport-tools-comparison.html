RHEL Kernel Backport Tools: A Three-Tier Comparison

Summary: Three Red Hat kernel backport tools occupy distinct tiers of automation. git-backport is a single-commit formatting utility. isb (Intelligent Subsystem Backport) automates the full multi-commit workflow with partially autonomous conflict resolution. frankenpatch uses autonomous AI agents for fully hands-off backporting. Each serves a different use case and audience.

Tool Overview

Tier 1   git-backport — Single-Commit Formatting

git-backport is a lightweight utility from the CentOS Stream kernel utils. It takes a single upstream commit hash, wraps it with RH metadata (JIRA ticket, CVE identifier, Signed-off-by), and produces a formatted patch file. The developer is responsible for everything else: identifying which commits to backport, ordering them, resolving conflicts, verifying builds, and iterating.

Typical usage:

git-backport --sign-off --jira RHEL-1234 --CVE CVE-2024-99999 <commit_hash> && git am -3 /tmp/0001.diff

Tier 2   isb — Interactive Multi-Commit Backport

isb (Intelligent Subsystem Backport) automates the entire multi-commit subsystem backport workflow while keeping the developer in control of judgment calls. It discovers scope paths, finds the divergence point between upstream and RHEL, classifies and filters commits, runs the cherry-pick loop with progress tracking and resume capability, and provides partially autonomous conflict resolution: out-of-scope files, MAINTAINERS, delete/modify conflicts, duplicate struct/union/enum definitions, and missing kernel API calls (e.g. kzalloc_obj) are all resolved automatically. Only in-scope content conflicts — the actual merge decisions — require human intervention, via patchpal (GUI) or manual editing.

Key features:

  • Commit list review: After classification, KEEP and OMIT lists are written to editable files. The script pauses so the user can review, add, remove, or reorder commits in another terminal before proceeding.
  • Single-step mode: isb --step (or x in the menu) applies only the next commit and stops, allowing careful inspection before continuing.
  • Patch regeneration: isb --regen (or p in the menu) rewrites commit messages with updated JIRA, Signed-off-by, or other metadata and regenerates the patch series — without re-running the entire backport.
  • Visual feedback: Animated spinners for every long-running operation: cherry-picking, conflict resolution, scope indexing, and build testing. No silent delays.
  • Patchpal integration: Prominent notification banner before each patchpal invocation, with automatic window focus/raise via xdotool or wmctrl.
  • Scope path editing: Individual paths editable (A–Z keys), removable (empty input), and addable (+) from the interactive menu.
  • Signed-off-by auto-detection: Reads from git config user.name / user.email if not provided.
  • Stale state detection: Detects external HEAD resets and discards stale resume state instead of silently picking up at the wrong position.
  • Git alternates: Uses git alternates for zero-copy, instant access to upstream commit objects from a local upstream repository.

Typical usage:

cd ~/kernels/centos-10 && isb

(Session parameters are prompted interactively on first run and reused automatically.)

Tier 3   frankenpatch — Autonomous AI Backport

frankenpatch uses LLM-powered AI agents (Claude via Google Vertex AI or local Ollama) with unrestricted shell and file access to autonomously resolve conflicts and fix build errors. The developer provides the commit list and reviews the results at the end. It builds kernels in Podman containers and uses a planner-executor agentic loop for iterative build-error fixing.

Typical usage:

uv run frankenpatch backport-cve --cve=CVE-2024-99999 --jira=RHEL-150000 --os=rhel --os-version=10 --commit=abc1234 /path/to/repo

When to Use Each Tool

Scenario Recommended Tool Why
Cherry-pick 1–2 known upstream commits git-backport Simple, fast, no setup. You already know exactly which commits you need.
Backport an entire subsystem across kernel versions isb Automates discovery of hundreds of commits, filters already-applied ones, handles the full loop with resume.
Backport with many complex conflicts and you want human control isb Interactive patchpal or editor lets you review each conflict. Build testing catches issues early.
Backport CVE fixes with AI assistance and you have cloud AI access frankenpatch AI agent can autonomously resolve conflicts and fix build errors. Best for teams with GCP/Vertex AI infrastructure.
Large-scale DRM subsystem backport (mega-patch workflow) frankenpatch Purpose-built DRM backport commands with AI-driven mega-patch conflict resolution.
Repeatable backports across point releases (10.1, 10.2, 10.3 ...) isb Session management remembers parameters. Output is organized by RHEL version. Reset and resume support iterative workflows.

Relationship Between Tools

These three tools are complementary, not competing. They represent increasing levels of automation for increasingly complex backport tasks:

  • A developer who needs to cherry-pick a single CVE fix uses git-backport.
  • A developer who outgrows single-commit picks because they maintain an entire subsystem across RHEL versions graduates to isb.
  • A team with Google Cloud / Vertex AI infrastructure that wants fully autonomous backporting uses frankenpatch.
Key insight: isb occupies the critical middle ground — it automates the tedious parts (scope discovery, commit filtering, cherry-pick looping, state management) while keeping the developer in control of the judgment calls (conflict resolution, build fixes). git-backport leaves too much to the developer; frankenpatch requires infrastructure most developers don't have.
